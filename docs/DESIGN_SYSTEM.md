# مصر رايح جاي — Design System وتصميم النظام
نسخة 0.1 · موقع سياحة وحجز رحلات بهوية مصرية، Laravel + React
(وثيقة المواصفات كما قدمها sayed بتاريخ 2026-11-22)

قرارات التنفيذ: Laravel كـ backend، وReact عن طريق Inertia.js مع SSR للـ SEO والسرعة، وقاعدة بيانات MySQL/PostgreSQL، وTailwind مربوط بالـ tokens، والموقع عربي RTL وإنجليزي من أول يوم.

## 1. فكرة الهوية
الشعار الجمالي: "فخامة الحجر والذهب". مش كارتون فراعنة ولا نقوش زيادة. التصميم هادي وواسع، تباين قوي بين ظلام الليل على النيل ودفء الحجر الرملي، وذهب بيظهر بحساب بس في العناصر المهمة.

مبادئ التصميم:
1. الفخامة بالتقشف: مسافات واسعة، نصوص قليلة، صور كبيرة. الذهب للتأكيد مش للزينة.
2. الأصالة بالتفاصيل: الزخرفة في الحدود والفواصل والأيقونات، مش في الخلفيات المزدحمة.
3. الحكاية قبل الحجز: كل رحلة ليها قصة، والحجز ييجي بعد ما الزائر يتحمس.
4. الوضوح في الحجز: صفحة الحجز هادية وخالية من الزخرفة.
5. ثنائي اللغة من الأساس: أي مكوّن يشتغل RTL وLTR بنفس الجودة.

## 4. الأنماط (Patterns)
### رحلة الحجز
1. اختيار الرحلة → 2. اختيار الموعد والعدد (السعر يتحدث لحظياً) → 3. بيانات المسافرين (الاسم كما في جواز السفر) → 4. المراجعة وسياسة الإلغاء → 5. الدفع والتأكيد برقم الحجز وإيميل/واتساب. المبدأ: صفحة واحدة متقسمة لخطوات مع حفظ التقدم.

### قسم تعلم اللغة الفرعونية
- مستويات قصيرة (10 دقايق للدرس): الأبجدية الأحادية، الأسماء والألقاب، الأرقام، كتابة اسمك، قراءة أسماء ملوك ومعابد.
- تمارين: مطابقة رمز بصوته، كتابة اسمك، اختيار المعنى، قراءة خرطوش.
- الربط بالرحلات: كل درس يقترح رحلة ذات علاقة.
- التمثيل الصوتي: النطق المعروض هو الـ transliteration المتعارف عليه عند علماء المصريات (يوضَّح للمستخدم).
- الرموز نص Unicode حقيقي مع aria-label بالوصف والمعنى.

## 5. تصميم النظام (System Design)
متطلبات وظيفية: تصفح وبحث وفلترة، صفحة وجهة، حجز ودفع، حساب وحجوزات، لوحة إدارة، قسم تعلم مع تتبع تقدم، إشعارات (إيميل/واتساب).
غير وظيفية: صفحة الرحلات < ثانيتين على موبايل متوسط، SEO ممتاز، منع الحجز المزدوج، أمان بيانات المسافرين والدفع.

المعمارية: المتصفح → Inertia + React (SSR) → Laravel (Controllers/Actions/Services) + Queue (Redis) للإيميلات والتأكيدات + Cache (Redis) للقوائم + Payment Gateway Webhooks → MySQL/PostgreSQL + Object Storage/CDN للصور.
سبب Inertia بدل SPA منفصل: routing وauth وvalidation من Laravel مباشرة وSSR للـ SEO وسرعة فريق صغير؛ وعند الحاجة لموبايل يُفتح API بجانبه من نفس الـ Services.

نموذج البيانات (مبدئي): destinations (slug، اسم ar/en، وصف، صور، إحداثيات) · trips (destination_id، slug، عنوان ar/en، مدة، مستوى، برنامج يومي، مشمول/غير مشمول) · departures (trip_id، تاريخ، سعة، مقاعد متبقية، سعر) · bookings (user_id، departure_id، حالة، إجمالي، عملة، رقم حجز) · passengers (booking_id، اسم، جنسية، رقم جواز مشفّر) · payments (booking_id، مزوّد، مبلغ، حالة، مرجع) · lessons (مستوى، ترتيب، عنوان، محتوى) · glyphs (رمز Unicode، تحويل صوتي، معنى، صنف) · lesson_progress (user_id، lesson_id، نتيجة، اكتمال) · translations أو أعمدة JSON.

Endpoints أساسية: GET /trips (فلترة) وGET /trips/{slug} · POST /bookings (pending مع حجز مؤقت للمقاعد) · POST /payments/webhook · GET /learn وGET /learn/{lesson} وPOST /learn/{lesson}/progress.

منع الحجز المزدوج: transaction مع lockForUpdate على صف الـ departure، خصم المقاعد، وحالة pending بمهلة (15 دقيقة) تتحرر بعدها المقاعد بـ job مجدول لو الدفع لم يتم.

الدفع: بوابة تدعم الجنيه وبطاقات الأجانب — مرشحون للمقارنة: Paymob وFawry محلياً، وStripe دولياً. التحقق من التوفر والرسوم الحالية قبل القرار (قرار الشركة).

الأداء والـ SEO: SSR لصفحات الرحلات والوجهات، slugs نظيفة، schema.org TouristTrip، hreflang عربي/إنجليزي، صور WebP/AVIF بأحجام متعددة وlazy loading وCDN، وCache للقوائم يُبطل عند تعديل الأدمن.

الأمان: تشفير رقم الجواز، HTTPS إجباري، CSRF، rate limiting على الدخول والحجز، عدم تخزين بيانات البطاقات إطلاقاً (البوابة تتعامل معها)، وصلاحيات واضحة للوحة الإدارة.
